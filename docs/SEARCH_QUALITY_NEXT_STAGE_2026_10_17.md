# 下一阶段计划：真实搜索失败归因与首轮改善

制定日期：2026-10-17。当前状态：已开始执行；P0 首批真实失败归因完成，P1 离线测量与部分运行态走查完成，P2 首轮抽取候选未通过准入。搜索质量修复尚未验收。依据当前工作树、搜索主线契约及本地真实搜索记录；不以历史测试通过替代当前质量验收。

## 目标与边界

下一阶段的交付是：对已经出现的真实搜索失败给出可复核根因，完成一轮有前后证据的通用修复，并用当前产品入口验证。优先回答“该找到的公司为什么没找到”和“返回公司的证据是否支持用户原意”。

产品仍只有发现页与公司业务页；行情继续维护，不推进旧 M2/M4/M5 产品扩展，不恢复财务或资讯展示。保留物理交互、显式 judge 选择、历史答案与 Web + Data / Harbor 契约。

计划本身不授权新的 Cloud 调用、训练、模型晋升、默认模型切换、提交、推送或部署。用户随后已明确要求按本计划开始执行；本轮完成本地日志审查、事实与召回诊断、离线测量工具和候选预览，并在隔离端口做无 judge 的页面走查。LIVE 按已有规则单独登记并取得调用次数与 USD 上限授权；不使用过去实验的余额。

### P0：先建立完整根因链

优先审查已有明确负反馈；相邻查询只用于定位，不自动当作新的失败。每个案例按下列链路逐层核对：

1. **原意与依据**：保留原查询和反馈。期望公司必须有可回指的可靠事实；没有期望名单时先审现有证据，不能凭常识补一份“正确答案”。
2. **事实覆盖与投影**：分别检查原始来源、结构化事实、corpus、检索文本和实际 judge 输入。事实已收录但没有进入有限输入预算，不能简单算作模型判断错误。
3. **候选召回**：检查 BM25、向量、融合、硬过滤和候选截断；记录目标公司在哪一步消失。候选全集、已判断公司与最终展示数量分别记录，不混用分母。
4. **判断**：仅在实际输入含足够事实且确实有该公司 decision 时评审误判；记录 matched、分数、evidenceRefs、实际身份、缺判断和失败。
5. **排序与展示**：检查服务端截取、结果资格、缓存、前端顺序、证据展开和公司页原记录恢复。去掉历史填充可能只产生诚实空结果，不能算作解决漏召回。
6. **运行**：单列超时、无配置、身份拒绝、损坏输入与日志缺失；不混入语义质量结论。

大小写或表达差异先在同一 judge、同一 corpus/向量/代码状态下比较；历史记录使用不同 judge 时不能据此归因于大小写。事实缺失区分 `CORPUS_MISSING_FACT` 与 `SOURCE_SURFACE_GAP`；无法下结论保留 unknown。

案例清单记录首次出现、独立 trace 数、反馈、影响、归因证据与状态。首轮审完现有高优先级失败，不规定必须凑满多少条自然查询。

### P1：让测量对应当前产品

复用现有观察与账本工具，为当前主线建立独立标识的测量模式。发现案例必须经 `runCompanyDiscovery`；HTTP 与浏览器走查另外验证 `/api/discover` 及 `/api/search` 别名、缓存和 trace，不用内部调用代替整个产品旅程。

- 旧 benchmark 原题、锚点、快照与历史 runner 模式保留。当前模式显式标入口/契约；行情题原样观察为范围拒绝，不能偷偷删除条件、改题或与旧模式混算质量。内部 comparison/explanation 观察单列，不能算当前发现页搜索数。
- 固定 HEAD、已跟踪 diff 与未跟踪源码哈希、corpus、向量/embedding、parser、capability/prompt、入口契约和实际 judge；新测量使用唯一目录。变更 corpus 或模型必须另建坐标，不称为同环境模型对比。
- 测量代码不读行情 state/calendar；历史工具需要的行情坐标留在历史模式。缺私有输入或不能复现时明确停止对应测量，不重建假数据。
- 真实案例诊断集与冻结评测集分开。审查标签注明人工或 agent-reviewed；未知不强制变成正负标签。模型应答不是 gold，点击与改写只是线索。
- 运行态走查覆盖正常匹配、零匹配、范围拒绝、DEGRADED、缓存命中、显式模型选择和公司页历史证据恢复，并检查窄屏/桌面与物理交互。先用受控离线条件验证；任何会触发 Cloud 的页面操作须纳入已授权预算。

### P2：按根因选择一条修复路径

| 证实的问题 | 允许推进的动作 | 不在本轮顺手扩展 |
| --- | --- | --- |
| 已有事实在 builder/投影中丢失 | 修复通用构建或投影机制，核对出处、预算、digest 与向量一致性 | 不手改公司语料、不补推断标签 |
| 事实在 corpus 中，但未进入候选 | 定位通用分词、索引、向量一致性、过滤或融合缺陷；只有真实失败证据支持才立项改动 | 不建型号/行业/公司词典，不为单题扩大候选预算 |
| 候选与输入充分，judge 仍错 | 固定输入记录判断问题；进入候选模型对比或独立 Laya 训练诊断 | 不改分数、不改答案名单、不无声换模型 |
| 返回正确但展示/缓存错误 | 修复结果截取、缓存隔离、证据恢复等确定性机制 | 不在前端重新判断语义或选择证据 |
| 现实事实存在但未覆盖其来源面 | 登记 surface gap、影响及证据，再按既有 pilot 闸门另行立项 | 不直接启用新采集面或 scheduler |

只选择一条有证据、收益明确的路径先做完。若根因只能通过尚未授权的 LIVE 或训练验证，先交付诊断与具体实验登记；继续完成不依赖它的离线工作，不用其他功能代替质量改善。

### P3：验收与停止条件

质量按查询族与失败层分别报告：已知有据目标的候选召回、最终展示与名次、前列结果证据支持、误入/证据不足、空结果是否合理、运行失败、延迟及已发生费用。目标集合不完整时只报“已核实目标的命中”，不称为全池召回率。

首轮通过必须同时满足：

- 优先失败可复核归因；至少一个已证实且可修复根因有机制层面的前后改善。若只有定位而没有改善，阶段状态为“诊断完成，质量修复未验收”。
- 目标案例及独立正负对照按修复前登记的检查项复核；无已发现的重大业务误入或证据强度/主体/方向/时点越级。样本规模、未审部分和未知项如实列出。
- 结果资格、空结果、DEGRADED、缓存/模型隔离、历史证据及范围拒绝保持；兼容测试通过只证明旧契约未坏。
- LIVE 比较在同一环境各至少两轮，独立于缓存回放；预算不足记录部分结果，不宣布稳定性或候选通过。未经 LIVE，只给离线可证明的结论。
- 先跑与改动相关测试，再在阶段收口运行必要的完整本地测试、typecheck、相关 lint、build、`corpus:check` 和 `publication:check`。只有触及维护侧时才追加其对账；不为搜索刷新行情。

出现事实/评测泄漏、证据越级或重大退化即停止推广并修正。需要上线时事先明确回退边界；历史答案不重算。报告分别列工程验收、搜索质量、模型候选与发布状态，不能合成一个 PASS。
