### M2.2 固定快照与共享刷新

- 既有 Data service 提供 `/market-snapshot`；请求驱动，线程合并并发刷新，没有第三个常驻组件。
- 交易中使用 60 秒刷新候选间隔；休市/盘前已拥有有效收盘快照时直接复用，不反复抓全池。
- 9:25–9:30 与 11:30–13:00 的时钟停顿有明确锚点；收盘数据源时间须达到 15:00。
- identity/date/time/数值/单位异常逐类记账；缺行与传输失败分开；当前零成交不推断成停牌。
- 采集跨日或跨交易阶段、覆盖或采集耗时不达标不发布；失败保留旧 pointer。
  Web 仍独立检查旧 pointer 的目标日与源端年龄；源已过期时旧文件不能冒充可用排行。
- `build_live_market.ts` 复用 `buildDerivedState`：纯确定性派生，不在 Python 再写一套排行/历史指标算法。
  source capture、公司池 SHA、历史日、行 SHA-256 校验后原子发布目录指针。
- 历史窗口引用 immutable EOD snapshot，不每分钟复制 60 天文件。
  若上一完整交易日不在历史窗中，Data 使用现有 refresh 命令补齐，再发布当前 quote snapshot；
  盘后包未发布就拒绝不完整历史，而不是少算一个交易日。`--through` 只允许过去日期。
- 搜索固定一次 manifest，行/上一日比较/答案缓存共用它；cache identity 包含 snapshotId
  与源端可用性，价格未变但源端时点改变也不会保留旧 caption。
- 纯公司发现缓存独立于市场 snapshot，不因每分钟行情刷新多付 Jev 判断成本。
- 结构化 `/api/market` 也刷新并按快照身份缓存，避免 spec-only LRU 保留旧值。
- 公司页报价 asOf 读取源端时间；fetchedAt 保留采集时间，二者分开。

实际发布：`2026-09-30_quote_0affe944-ed74-43b3-9492-8c842d508726`。
采集 12:40:50–12:40:54（北京时间），3.907 秒；源端最早 09-30 15:34:18，最晚 16:15:00；
5,556 可排行 + 11 无成交，无缺失/异常。本地 Web 与 Data 已更新并上线。

## 尚未通过的验收与停止条件

1. 当前是休市期，不能证明交易中源时间刷新、午休/竞价真实响应、60 秒刷新在持续使用下的延迟。
   开市后须在竞价、连续交易、午休、收盘各采集实际 snapshot 并检查源年龄/覆盖/排序。
   当前门槛不达标就拒绝发布，不能降低门槛以显示实时，也不能写盘中 PASS。
2. 源端量比的计算基准仍未核验，保持禁用；没有通过启用条件，不拿 20 日比值代替。
3. immutable quote snapshot 当前保留本地出处链。持续运行后需按保留期限收束磁盘文件，
   引用中的历史 snapshot 与请求固定快照必须保留；本轮没有加入 scheduler 或盲删历史目录。

因此 **M2.1 的收盘验收通过、M2.2/M2.3 工程完成，但 M2 仍带上述验收条件**。
M3 不在本轮实施，也不因当前工程测试通过自动解除业务资格/全池 TopK 契约的闸门。
