# M5：发现结果的跨页一致性

2026-10-15 用户明确授权定义并实施本里程碑。M5 独立交付，不据此补记 M2 持续盘中可用性或 M4 本人真实使用已通过。

## 问题与范围

公司页目前把所有没有语义评分的搜索描述为“基础检索排序”，包括纯行情排行和历史答案不可恢复的情况；原搜索的排名、行情指标和时点也未呈现。公司页另行获取的报价可能与搜索快照不同，必须让用户区分这两份事实。

M5 在既有公司页呈现原搜索上下文，不新增产品页面、行情指标、语义规则或模型调用。

## 契约

- URL 的 `s`（search trace id）与 `q` 共同定位已保存答案，公司代码必须存在于该答案。URL 里的评分、能力标签不作为事实。没有唯一 trace、记录缺失/损坏、查询不一致、公司不在结果中，都明确不可恢复，不按相同查询猜历史答案，不重新搜索。
- 原排名、排序说明、行情指标、日期、源端时点范围、覆盖和扫描不完整状态来自该答案。TopN 子集保留原行情名次，不按子集位置重新编号；旧行情记录缺少名次就显示未记录。
- 语义判断、实际模型和逐字证据读取原答案记录；当前选择、当前 corpus、后续市场快照不得替换历史内容。未知模型身份或缺失证据如实展示；查看页面不触发解释调用。
- 公司页行情标明自己的源端时点及采集时点（北京时间）；存在原搜索行情时，明确它是另行获取的报价，可能与原搜索不同。源端时点缺失不以采集时间代替。
- 直接访问 canonical 公司页不编造搜索上下文。保持物理交互及原有公司资料、财务、公告、研报的失败语义。

## 验收

使用合成答案与离线测试覆盖：纯行情、语义判断、降级、TopN 子集名次、预算停止、缺失/错误链接、旧记录字段缺失，以及市场/模型变化后的历史内容隔离。复用证据与缓存回归；执行 typecheck、相关 lint、生产构建与 publication 检查。新增 Cloud 调用为 0，不把工程验证称为发现质量或本人使用验收。

- 新增 12 项离线测试，含公司页服务端渲染、冷模块加载后的磁盘恢复、缓存别名 trace、同查询不同答案、坏哈希、URL 评分/能力伪造、缺失历史、证据完整性、行情/模型/语料隔离及时间展示。
- 连同既有证据、答案缓存和 telemetry 行为不变回归，共 42 项相关测试通过。未将本轮局部检查记为完整项目回归或发现质量通过。
