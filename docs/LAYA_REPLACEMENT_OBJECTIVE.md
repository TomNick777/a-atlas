# Laya 持续训练目标

用户目标（2026-10-12）：在统一 Atlas 工程内持续训练 Laya，达到能够替代 Jev 的程度。模型研究属于正式项目，不阻断已经可靠的工程合并；两项完成状态分别记录。

## 目前基线

Jev 实际已验证身份为 jev-1.13.0；Laya 保留原登记 active v4.1。v7、v10 为失败候选，不晋升。v10 独立关系 10/20、证据解释 13/20，match/comparison/eligibility 各 2/2；这不足以说明泛化或替代能力。本轮新增 Cloud 费用为 0。

## 替代如何判定

- 四项 capability 和 market eligibility 遵守同一事实、证据、known、分数和失败契约；不使用第二个 judge 兜底，未知如实标记。
- 在预登记的独立样本和真实搜索 trace 上按能力、查询族比较 Jev/Laya，覆盖正例、负例、关系强度、方向、披露时点与缺事实。逐项报告，不用总分掩盖局部失败。
- 新训练样本按公司、披露来源、表达家族隔离，验证和盲测各能力含正负例；训练标签有出处，教师分数不直接作为真值。冻结验收题不参与补样和调参。必要的新评估集在训练前封存，旧观察继续保留。
- 关键关系与解释不能声称强于所给证据；普通排序差异按族评审。不能以“权重更新成功”或单一 validation loss 宣称替代成功。
- 固定代码、corpus、市场快照、prompt、实际模型和评估版本做重复检查，记录稳定性、延迟、GPU 占用、队列等待和失败行为。费用预算先登记，不自动追加 Cloud 调用。
- 候选通过后才允许晋升，实际装载身份和回退必须验证。把默认模型改为 Laya 需要明确决定，训练不自动改变用户选择。

## 下一轮训练的输入

先分析公司/来源/表达隔离后的验证与盲测错误，审核标签和原文完整性，区分数据缺事实、标签错误、表达覆盖不足、模型判断错误。基于训练侧可泛化的缺口补独立样本，再预登记一次训练试验；不根据冻结题失败逐条补同义词、公司或生产规则。现有 v10 验证损失按能力差异很大，下一步是数据/训练机制诊断，而不是反复用同一独立验收集选学习率。

工程入口统一为 `data/train/`、`training/laya/`、`models/runs/` 和 `reports/laya-evaluation/`；详见运行契约。真实数据、权重、恢复状态及评估观察留在本机，不进入公开 Git 历史。
